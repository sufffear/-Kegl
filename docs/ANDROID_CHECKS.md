# Проверки Android

Требования: Python 3 (стандартная библиотека), JDK 21, SDK проекта,
Gradle Wrapper. Запуск из корня репозитория. Скрипт сам сохраняет полный вывод;
не нужно оборачивать каждую команду в перенаправления и разбирать XML вручную.

| Команда | Что выполняется |
|---|---|
| `python3 scripts/check-android.py changed --dry-run` | Выбор проверок без запуска Gradle |
| `python3 scripts/check-android.py changed` | Связанные тесты для текущего diff, включая staged/untracked/deleted |
| `python3 scripts/check-android.py changed --base origin/main` | Проверка изменений всей ветки относительно выбранной базы |
| `python3 scripts/check-android.py related ChantalHomePresenceTest ChantalNarrativeUiTest` | Явно выбранные классы одним запуском Gradle |
| `python3 scripts/check-android.py compile` | Только `:app:compileDebugKotlin`, если тесты не требуются |
| `python3 scripts/check-android.py full` | Все unit/Robolectric тесты, включая стресс, сохранения и recovery; без APK |
| `python3 scripts/check-android.py release` | Все тесты + APK за один Gradle-запуск + обязательная проверка постоянного сертификата |
| `python3 -m unittest discover -s scripts/tests -q` | Проверка самого запускающего скрипта, без Android/Gradle |

Тестовая задача уже включает нужную компиляцию приложения, ресурсов и тестов;
не запускать `compile` отдельно перед ней. Gradle использует штатный incremental
build/cache. Никаких автоматических повторов, очистки или принудительного
повторения уже актуальных задач нет. Результат из cache/UP-TO-DATE помечается
отдельно от нового исполнения.

## Как выбираются тесты

Небольшая явная карта `SCOPES` в скрипте содержит проверенные связи компонентов
представления/транспорта с unit и интеграционными тестами. Изменение тестового
класса добавляет этот класс. Хранилище, движок, жизненный цикл тренировок,
ресурсы, схема, Gradle-зависимости и любой неизвестный Android-файл переключают
на полную регрессию. Удаление теста/правка тестового helper также требуют full.
Объединяются все найденные классы, повторных запусков одного класса нет.
Если в рабочем дереве остались уже проверенные правки прошлых заданий, `changed`
включит и их. Для текущей небольшой правки можно выбрать `related` по её
фактическому diff и предыдущим результатам; сомнение означает выбор `full`.

Для одних документов/инструментов Android не запускается; при правке инструментов
нужно выполнить их собственные тесты и dry-run. Карта — консервативная подсказка,
не доказательство отсутствия зависимостей. Если эффект шире известных связей,
использовать `full`, а не сужать проверки ради скорости. После чистого commit
`changed` относительно HEAD ничего не обнаружит: указывать `--base` нужного diff.

## Вывод и ошибки

Каждый запуск Gradle пишет в игнорируемый `build/checks/<UTC>-<pid>/`:

- `gradle.log` — полный вывод;
- `summary.json` — статус, число passed/failures/errors/skipped, источник отчётов;
- `xml/` — копия XML результатов этого выбора;
- `signing.log` — подробности проверки подписи для release.

В консоль идут краткий итог и до трёх сообщений о проваленных тестах.
При ошибке компиляции выводится короткий фрагмент Gradle. Старые XML после
неудачной компиляции не засчитываются; успешный тестовый запуск без отчётов
считается ошибкой проверки. Код выхода ненулевой при ошибке Gradle/подписи/отчёта.
Проанализировать конкретную причину, исправить, повторить связанный набор.
После существенного исправления или перед выпуском выполнить full/release.

## CI и выпуск

GitHub workflow `build-apk.yml` запускается вручную (`workflow_dispatch`). В нём
`release` сохраняет весь набор тестов и строгую проверку прежнего сертификата.
Проверки не дублируются отдельным запуском компиляции/тестов после сборки.
APK выгружается только при успехе. Логи и тестовые отчёты выгружаются также при
неудаче. Автоматических сборок на push и git hooks нет; «автоматический выбор»
означает выбор внутри явно запущенного `changed`, а не скрытые фоновые действия.

Перед выпуском остаются проверки на телефоне: установка обновления, полный
игровой цикл, поворот/kill процесса, звук/фон и жесты. Скрипт не подменяет их
Robolectric и не делает платных запросов ИИ. Финальный сброс — отдельный этап.

## Другое окружение

При необходимости `ANDROID_GRADLE_BIN` задаёт путь к уже установленному Gradle
вместо wrapper. `ANDROID_GRADLE_ARGS` — дополнительные аргументы (разбираются
без shell), например `--no-daemon -I /absolute/path/local-init.gradle`.
Прокси/сертификаты настраиваются локально; адреса конкретной облачной машины
в репозиторий не встроены. Не передавать секреты в аргументах Gradle.
Для выпуска необходимы SDK/apksigner и прежний игнорируемый ключ подписи;
скрипт новый ключ не создаёт и проверки сертификата не обходит.
