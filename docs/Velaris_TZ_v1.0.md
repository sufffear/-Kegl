# Velaris — техническое задание v1.0

Дата: 03.11.2026. Язык приложения и общения с владельцем: русский.
Статус: новая основная редакция после принятого аудита. Заменяет требования v0.3. При конфликте использовать v1.0.
Назначение: личное нативное Android-приложение для Samsung. Публикация в магазине не входит в текущую задачу.

## 1. Продукт и окончательные решения

Velaris объединяет спокойный интервальный тренер тазового дна и самостоятельный офлайн-романтический сериал. Обе части доступны без регистрации и интернета.

Принятые изменения:
- Девять обязательных подходов отменены. Утро / Обед / Вечер — группы плана, а не назначение нагрузки.
- История полностью доступна независимо от упражнений. Нет выдачи сцен за нагрузку, валюты, штрафов, серии дней или наказания за пропуск.
- После завершения упражнения можно перейти к текущей сцене. Это удобный переход, а не награда или разблокировка.
- Число глав и эпизодов не связано с количеством упражнений или календарных дней.
- Сначала проверить установку APK и фоновый механизм на Samsung, затем разрабатывать основной интерфейс.
- В уведомлении нужна кнопка «Пауза». Образцы сигналов доступны прямо в настройках.
- APK, исходники и отчёт появляются после каждого этапа, а не только в конце.

Приоритеты: безопасность поведения → сохранность данных → работа таймера и сигналов → понятный интерфейс → атмосфера → расширение истории.

## 2. Границы и безопасный запуск

Приложение не диагностирует состояние мышц, не оценивает качество сокращения и не обещает лечение или улучшение сексуальной функции. Таймер фиксирует прохождение последовательности, а не подтверждает правильность физического упражнения.

До выбора подходящей программы доступен только режим демонстрации. Демонстрационные значения предназначены для проверки программы: экран явно сообщает «Демо — не выполняйте упражнения по этим сигналам». Они не становятся реальной программой после обновления.

Первый экран знакомства кратко объясняет сигналы, паузу, отсутствие автоматической оценки техники и необходимость остановиться при боли/дискомфорте. Рекомендовать согласовать программу со специалистом. ИИ-разработчик не назначает интервалы, повторения, пределы нагрузки или адаптацию по собственной инициативе.

Для реального режима нужны выбранная пользователем подходящая программа и записанный источник её параметров. Клинические решения остаются открытыми и блокируют только реальную тренировку, не разработку и чтение. Согласие с ТЗ не является медицинским назначением.

Технические параметры валидировать: положительная длительность фаз, целое положительное число повторов, допустимая длина последовательности, отсутствие переполнения и нулевых циклов. Технические ограничения не называть безопасными медицинскими пределами. Конкретные ограничения документировать отдельно от программы.

## 3. Инструменты и поставка

Основная стартовая среда: Google AI Studio, Build → Android. Нативный Kotlin + Jetpack Compose + Material 3. Один модуль app, одна Activity, пакеты ui / domain / data. Не заменять проект сайтом, PWA, React, Flutter или Capacitor.

Room хранит тренировочные попытки и чтение; DataStore — настройки. ViewModel + StateFlow, однонаправленный поток данных. Чистый Kotlin-движок фаз тестируется без экрана. Android-компонент управляет фоновым выполнением и сигналами. UI только отображает состояние и отправляет команды.

Не подключать Firebase, Gemini API, облачную БД, аналитику, авторизацию или сетевую генерацию. Среда разработки может пользоваться интернетом; готовое приложение — нет. Проверить итоговый merged manifest, не запрашивать INTERNET без нового обоснованного требования.

Если AI Studio не даёт нужного доступа к сборке/диагностике/выгрузке APK: сохранить ZIP исходников и продолжить тот же проект в Antigravity с установленными Android SDK/JDK либо подходящем Android-окружении. Не переписывать приложение на другой стек. Не предполагать наличие компьютера у владельца.

Зафиксировать проверенные версии JDK, Gradle wrapper, Android Gradle Plugin, Kotlin, Compose, compileSdk, targetSdk, minSdk. Выбрать совместимые стабильные версии по актуальным официальным источникам; не использовать динамические версии «+». Записать фактические Android/One UI и модель целевого телефона, не угадывать.

## 4. Визуальный стиль

Тёмный атмосферный минимализм, статичные градиенты, очень тонкие векторные силуэты гор. Без портретов, видео, бесконечных переливов и тяжёлых растровых фонов.

Пять тем:
1. Рассвет — фиолетовый/розовый, по умолчанию.
2. Небо — тёмно-синий/голубой.
3. Северное сияние — бирюзовый/изумрудный.
4. Закат — оранжевый/тёплый красный.
5. Сакура — розовый/лиловый.

Для каждой темы заранее задать проверенные семантические цвета фона, поверхности, текста, кнопок, ошибки, завершения и фокуса. Не генерировать контраст случайно во время работы. Целевые коэффициенты: обычный текст ≥4.5:1; крупный текст и значимые элементы управления ≥3:1. Проверять реальный фон под текстом, а не крайние цвета градиента. Текст на стабильных поверхностях.

Завершение: галочка и текст «Завершено», небольшой зелёный акцент. Не перекрашивать целиком карточку в кислотный зелёный. Состояние различимо без цвета. Области касания не менее 48 dp, подписи для TalkBack, масштаб текста до 200% без потери функций. Анимации 150–200 мс с уважением системного отключения анимаций. Не озвучивать каждое обновление секунды через TalkBack.

## 5. Экраны и навигация

Пять основных областей: главная, план тренировок, активный подход, чтение, настройки. Знакомство/подтверждения/список глав могут быть компактными встроенными панелями, без новых верхнеуровневых разделов.

### Главная
Две крупные равноправные карточки: «Тренировка» и «История». При стандартном размере текста видны без прокрутки на целевом Samsung; при крупном — разрешена прокрутка.

Тренировка: «Сегодня X из N», где N — число запланированных подходов текущего дня. При N=0 — «Сегодня без тренировок», а не 0/0. Если реальная программа не выбрана — «Демонстрация». Показать следующее назначенное упражнение и переход к плану.
История: название текущей главы, короткий прогресс и «Продолжить чтение». Непрочитанное считать по содержимому, а не по выдаче наград.

Во время активного подхода отображать «Вернуться к тренировке» с её состоянием. Возврат на главную, чтение или настройки не создаёт новый таймер и не теряет текущий.

### План тренировок
Вкладки «Утро / Обед / Вечер». В каждой — только упражнения выбранного плана. Пустая вкладка сообщает «На это время ничего не запланировано».

Каталог типов: «Быстрые», «Медленные», «Удержание»; подписи объясняют конфигурацию выбранного протокола. «Медленные» и «Удержание» не должны быть двумя одинаковыми карточками с разными названиями. Если подходящего различия в выбранной программе нет, не создавать лишний тип. Параметры не выдумывать.

По умолчанию открывать первую группу с незавершёнными назначенными упражнениями в порядке Утро → Обед → Вечер, независимо от часов. Если всё завершено — текущую по времени группу. Ручное переключение доступно; вкладки не запрещают запуск в другое время.

Все запуски ручные. Завершённый слот нельзя выполнить повторно в ту же дату; его описание можно открыть. Незавершённая/остановленная попытка не блокирует слот навсегда. Нет долга за вчерашние упражнения и кнопки «догнать нагрузку».

### Активный подход
Большое кольцо, оставшиеся секунды фазы, подпись «Сокращение» / «Расслабление». Отдельно: «Повтор 3 из 8» и оставшееся активное время всего подхода. Цвет дополняет текст, но не заменяет его.

Кнопки «Пауза» и «Остановить». На паузе — «Продолжить» и «Остановить». Индикатор фактического аудиовыхода: наушники/динамик/тихий режим; если маршрут не определён, не показывать ложное подтверждение наушников.

После завершения: «Подход завершён», необязательная оценка «Легко / Нормально / Тяжело», действия «Читать историю» и «К плану». Пропуск оценки не отменяет завершение. Оценка не меняет нагрузку автоматически.

### Чтение
«Книга» — прокрутка по умолчанию; «Пошаговый» — смысловые фрагменты и кнопка «Далее». Есть возврат к предыдущему фрагменту и навигация по доступным главам.

Сохранять storyId / sceneId / fragmentId и смысловую позицию, а не только пиксели. Переключение режима и размера текста сохраняет место по возможности до того же фрагмента. Изменения ответов и позицию записывать при выборе/переходе и с умеренным debounce прокрутки, не только при закрытии экрана.

Настройки размера текста, межстрочного интервала и нейтрального тёмного фона чтения. Настроение сцены может менять небольшой акцент, но не пользовательскую тему и читаемость.

### Настройки
Один прокручиваемый экран с группами: темы; план/параметры; звук и вибрация; чтение; данные; сведения о версии. Не требовать, чтобы все группы помещались на один экран без прокрутки.

Настройки интерфейса сохранять сразу. Изменение параметров не меняет запущенный подход. Изменение расписания применяется со следующего дня, с понятной подписью. Сегодняшний снимок плана и завершённые слоты не пересоздавать. Не допускать дублирования выполненного упражнения через изменение плана.

## 6. План и время

План содержит стабильный ID, версию, источник, список групп и назначений. Каждое назначение имеет стабильный ID и снимок протокола. Число подходов переменное. Не существует зашитого знаменателя 9.

День сменяется в местную полночь. При создании попытки фиксировать локальную дату, ZoneId, абсолютное время старта и версию протокола. Начатое до полуночи относится к дате старта. Новый день не прерывает старый активный подход; второй запуск запрещён до его завершения/остановки.

Для новых запусков использовать текущую локальную дату телефона. При смене зоны/ручной даты существующие записи не переименовывать. При возвращении к уже существующей дате её слоты и завершения повторно использовать. Не создавать сложную защиту от намеренного изменения часов. Монотонный таймер не зависит от перевода системного времени.

## 7. Машина состояний и прерывания

Состояния: IDLE, PREPARING, RUNNING, PAUSED, INTERRUPTED, COMPLETED, STOPPED. Внутри RUNNING — индекс повторения, фаза и её остаток. В приложении максимум одна активная попытка, включая подготовку и паузу.

Старт → подготовка с тремя короткими сигналами → последовательность. Подготовка и пауза не считаются активным временем. После подготовки явно подать сигнал текущей фазы.

Пауза: немедленно остановить активное время и метроном, сообщить «Пауза — расслабьтесь», сохранить состояние. На паузе не оставлять команду сокращения как актуальную.

Продолжение: только вручную, три сигнала, затем остаток текущей фазы. Не повторять полностью прерванное сокращение и не добавлять активные секунды незаметно. Это фиксированная техническая семантика для демо; допустимость дробления сокращения и ограничение длительности паузы должны быть отдельно согласованы в реальной программе. Без такого правила возобновление реальной тренировки после прерывания не включать.

Остановить: сначала пауза, затем диалог «Завершить без зачёта?» с действиями «Завершить» / «Остаться на паузе». Отмена диалога/Back оставляет паузу. Не использовать неоднозначное «Да/Нет».

Звонок/потеря требуемого аудиофокуса/отключение использовавшихся наушников: пауза, без автовозобновления. Причина отображается. Если аудиофокус недоступен при запуске, не начинать звуковую последовательность без предупреждения. Звонки оператора и мессенджеров, тихий режим и DND проверить отдельно. Не обещать, что один callback аудиофокуса обнаруживает все звонки. Не запрашивать доступ к журналу звонков и контактам.

Экран уничтожен, сервис жив: подход продолжается. Процесс/сервис действительно погиб: восстановить INTERRUPTED, не считать время после последней подтверждённой точки. Предложить продолжить подтверждённое состояние или начать новую попытку. После перезагрузки ничего автоматически не запускать. elapsedRealtime прошлой загрузки не сравнивать с текущей.

Если планировщик существенно задержал команды: не проигрывать все пропущенные сигналы пачкой и не засчитывать невыполненную последовательность молча. Перейти в прерванное/паузу и показать проблему. Порог задержки документировать и тестировать, не объявлять медицинским нормативом.

## 8. Звук, вибрация и фон

Сигналы: сокращение; расслабление; подход завершён; группа завершена. На последнем назначенном упражнении группы финальный сигнал заменяет обычный сигнал подхода; двойного финала нет.

Необязательный тихий метроном. У сигналов и метронома отдельные уровни внутри приложения; они не должны менять системную громкость телефона. Образец сигнала воспроизводится нажатием в настройках, отдельный экран диагностики не нужен. При совпадении тика и команды пропустить тик, не заглушать команду. Нет сложного автоматического изменения громкости.

Тихий режим: различимые вибрации вместо аудио. Показать доступность вибратора, не обходить DND. Проверить различимость в руке/кармане и поведение системных настроек. Отсутствие возможного канала сигнала не выдавать за успешно работающий «невидимый тренер».

Foreground service выбирать по реальному назначению согласно текущему Android API. Отдельно обосновать звуковой и чисто вибрационный режим. Не использовать фиктивные сенсорные разрешения, бесшумное воспроизведение или постоянную перезагрузку shortService ради обхода ограничений. Оценить specialUse только при реальном соответствии и документировать последствия для будущей публикации.

Сам foreground service не гарантирует бодрствование CPU. При необходимости минимального wake lock ограничить его активной работой, задать timeout и гарантированное освобождение на паузе/остановке/ошибке. Не применять WorkManager как секундный таймер. Не обещать точность реального времени; измерить задержки и ограничения.

Уведомление: нейтральное «Velaris · Сессия», состояние и кнопка «Пауза». Нажатие на уведомление открывает текущий подход. На паузе предложить открыть приложение; возобновление остаётся явным. На экране блокировки не показывать интимные параметры и текст истории. Отказ в разрешении уведомлений проверить и объяснить его последствия по фактическому Android, без выдуманных блокировок.

## 9. Хранение и целостность

Время считать монотонными часами, UI не является источником истины. Сохранять точки при старте/смене фаз/паузе/возобновлении/остановке/завершении и примерно каждые 5 секунд активной работы. Запись не на каждый кадр. При жёстком завершении процесса возможна потеря неподтверждённого промежутка: обычно до интервала точки плюс задержка записи. Не обещать абсолютные 5 секунд и не достраивать нагрузку догадкой.

Завершение попытки и запись результата — одна Room-транзакция. UI вычисляет галочку из сохранённого результата. Уникальность завершения по dailySlotId. Повторный callback, быстрые нажатия и восстановление не дают второе завершение. Чтение/контент никак не участвуют в этой транзакции.

Основные сущности:
- TrainingPlan(id, version, source, effectiveFrom, assignments).
- DailyPlan(id, localDate, planVersion): снимок назначений дня.
- DailySlot(id, dailyPlanId, assignmentId, group, protocolSnapshot); уникальность dailyPlanId + assignmentId.
- WorkoutRun(id, slotId, status, startedAt, startDate, zoneId, protocolSnapshot, confirmedActiveMs, phaseState, checkpoint, interruptionReason, demo).
- WorkoutCompletion(runId, slotId UNIQUE, completedAt, optionalDifficulty).
- StoryPackage(id, version, schemaVersion), StoryScene, StoryFragment, Choice.
- ReadingProgress(storyId, sceneId, fragmentId, position, mode), StoryFlags, ChoiceSelection.
- Preferences: темы, звук, вибрация, типографика, фон чтения.

StoryUnlock удалён: разблокировки нет. Демо-данные имеют отдельное пространство/признак и исключены из реальной статистики и резервной копии реального прогресса. Нельзя выпускать случайные фиктивные завершения.

Миграции Room обязательны; запрещён destructive fallback для пользовательских данных. Ошибка БД показывается честно, не заменяется чистой базой молча.

## 10. История

Оригинальный связный взрослый романтический сериал: юмор, интрига, эмоциональные повороты, чувственное напряжение. Все романтические персонажи совершеннолетние, отношения строятся на согласии. Нет онлайн-чата и генерации во время чтения.

Для MVP девять оригинальных пилотных сцен; это тестовый объём, не обязательный день истории. До этапа истории допустимы 2–3 коротких нейтральных фрагмента-заглушки с явным обозначением.

Сцены объединены в главы и заканчиваются естественно. Варианты подачи: повествование, диалог, небольшая записка. Редкие выборы из двух ответов влияют на ближайший фрагмент и 2–3 ограниченных сюжетных флага с последующими упоминаниями; ветви сходятся. Никакого бесконечного дерева вариантов.

Ответ в сцене фиксируется при первом выборе; перечитывание показывает тот же вариант. Сброс истории — отдельное явное действие с подтверждением, не влияет на тренировки. Режим просмотра альтернатив не входит в MVP.

После перерыва предложить короткое заранее написанное «Ранее в истории», без спойлеров и сетевого AI. Все сцены доступны сразу, читать можно по порядку или вернуться через список глав. В конце — «Вы прочитали доступные главы», доступно перечитывание. Тренировки продолжают работать.

Контент bundled JSON с schemaVersion, packageId, version, стабильными ID сцен/фрагментов/выборов, порядком, главами и условиями флагов. Валидировать уникальность ID, ссылки, варианты, достижимость и завершение ветвей. При изменении пакета сохранять ID; для удалённых фрагментов иметь отображение на новый или ближайший доступный без аварии. Исходники текстов входят в проект.

## 11. Приватность, обновления, резервирование

Нет аккаунтов, аналитики, рекламы, API-ключей и телеметрии. В системных логах не печатать тексты истории, оценки и подробные личные записи. Удаление всех данных только через явное подтверждение в настройках.

По умолчанию исключить пользовательскую БД и настройки из автоматического облачного Android Backup; настроить правила переноса/резервирования по поддерживаемым версиям ОС, проверить ограничения производителя. Не обещать абсолютную изоляцию от функций системы. Объяснить выбранную политику в README.

Локальный ручной экспорт/импорт прогресса через системный выбор файла включить до личного пилота. Формат версионированный, содержит реальные результаты, планы, позицию и выборы, настройки; без ключей подписи и демо. Перед экспортом предупредить, что файл содержит личный прогресс и хранится там, где выберет пользователь. Не загружать его автоматически.

MVP-импорт заменяет текущий прогресс после ясного подтверждения. Сначала полностью проверить формат/версию, затем применить атомарно; повреждённый файл не изменяет данные. Не поддерживать сложное слияние. Экспорт/импорт во время активной попытки недоступен до её остановки. Сохранённая попытка никогда не запускается автоматически после импорта.

Постоянные applicationId и signing key обязательны для обновлений поверх установки. Ключ/пароли не коммитить и не класть в общий ZIP исходников; способ сохранности ключа документировать. versionCode увеличивать. При переходе между средами проверить совместимость подписи до установки. Не советовать удалять приложение как обычный способ обновления.

## 12. Этапы и условия перехода

Каждый этап: исходники, результат сборки, доступный APK, тестовый отчёт, известные ограничения, понятная инструкция владельцу. Результаты физических тестов только после реального выполнения пользователем/разработчиком. Не писать «протестировано на Samsung» на основании эмулятора.

0A. Проверка среды и доставки: минимальный нативный проект, сборка, запуск эмулятора, сохранение исходников и реальный путь установки APK владельцу. Проверить доступность Android в его аккаунте. Нет подтверждённой доставки — записать блокер и предложить экспорт/другую среду, не подменять APK веб-ссылкой.
0B. Технический стенд: тестовые фазы без физического выполнения, звук/вибрация, корректная служба, пауза, уведомление, лог событий без личных данных. Samsung: экран выключен, наушники, звонки, уничтожение процесса. Не начинать основную оболочку, скрывая непроверенный фон.
1. Интерфейс: пять областей, пять тем, доступность, DataStore, демо-план и заглушки истории. Подключить существующий тестовый движок, не создавать независимый таймер в Compose.
2. Движок и данные: Room, переменный план, машина состояний, транзакции, восстановление, полночь/зона, обработка разрешений. Все тесты двигать через управляемые часы. Реальное выполнение остаётся закрытым, если программа не выбрана.
3. История: девять пилотных сцен, схема и валидатор JSON, два режима, позиции, флаги, перечитывание, отсутствие зависимости от тренировок.
4. Сохранность и обновления: миграции, подпись, APK поверх предыдущего, экспорт/импорт, backup-политика, отсутствие сети и секретов. Исправить ошибки.
5. Личный пилот: несколько дней на физическом Samsung; фиксировать удобство, ошибки и ограничения. Если программа ещё не выбрана — только демо и чтение. После успешного пилота добавить недельный обзор и расширять сериал. Импорт новых глав из файла — следующий релиз, не обязательный MVP.

## 13. Матрица приёмки

| Проверка | Ожидаемый результат |
|---|---|
| Повторный быстрый старт | Только одна активная попытка |
| Уход на главную/чтение и обратно | Один и тот же таймер, состояние сохранено |
| Пауза 60 секунд | Активное время не выросло |
| Отмена диалога остановки | Осталась пауза |
| Повторный сигнал завершения | Одна запись и одна галочка |
| Конец/ошибка контента | Завершение тренировки сохраняется |
| Звонок, Bluetooth-disconnect | Пауза, нет автовозобновления; результат записан для каждого канала |
| Тихий режим + блокировка | Реально различимые сигналы либо честно указанное ограничение |
| Смерть процесса/перезагрузка | Прерванное состояние, без времени простоя и автозапуска |
| Задержка планировщика | Нет пачки команд и фиктивного завершения |
| Полночь/смена зоны/перевод часов | Дата старой попытки неизменна, нет дублей |
| Изменение настроек в подходе | Текущий снимок протокола неизменен |
| N=0 и всё завершено | Корректные пустые/финальные состояния |
| Смена режима чтения/шрифта | Сохранён смысловой фрагмент |
| Перечитывание | Сохранены ответы, тренировки не изменились |
| Текст 200%, TalkBack, пять тем | Доступны все действия, нет обрезанных кнопок |
| Обновление APK без удаления | Прогресс/настройки/ответы сохранены |
| Экспорт → импорт | Восстановление корректно, активная тренировка не стартует |
| Повреждённый импорт | Старые данные не изменились |
| Авиарежим | Основные функции доступны |

## 14. Правила AI-разработчика

Выполнять только текущий заказанный этап; исправления внутри этапа делать самостоятельно. Не задавать владельцу вопросы о версиях библиотек и стандартных инженерных решениях: выбирать обоснованно и объяснять коротко. Уточнять только блокирующие продуктовые решения и медицинскую программу. После отчёта ждать команды на следующий этап.

Поддерживать docs/BUILD_STATUS.md: среда, версии, последний успешный APK, этап, выполненные проверки с доказательствами, блокеры и следующий шаг. Хранить docs/DECISIONS.md с инженерными решениями, docs/TEST_LOG.md с результатами. Статусы тестов: PASS / FAIL / NOT RUN; не выдавать NOT RUN за успех.

ТЗ хранить в docs/Velaris_TZ_v1.0.md. При каждом этапе сверяться с ним. Не удалять работающие возможности ради новой. Резервировать исходники после успешного этапа; git, если доступен, без обязательной внешней синхронизации. Не публиковать приложение и не подключать платные сервисы без отдельного поручения.
