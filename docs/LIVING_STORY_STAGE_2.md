# Живая Шанталь — этап 2: надёжный прогресс

## Изменения
- Room v6: цельный JSON-агрегат Шанталь, revision, уникальные подтверждения,
  неизменяемые записи событий и маркеры завершения восстановления. Аддитивная
  MIGRATION_5_6; экспортирована схема app/schemas/.../6.json.
- Старый JSON schemaVersion1 импортируется однократно. После импорта Room —
  единственный источник истины; legacy SharedPreferences не обновляются.
  Null-агрегат является явным пустым состоянием, не поводом повторно импортировать.
  Ошибки JSON/неизвестные версии не заменяются пустым сохранением.
- confirmJourney одной SQLite-транзакцией сохраняет результат выбора, награды,
  принятый эпизод, receipt и событие. Экран показывает результат после commit,
  больше не вычисляет награды самостоятельно. Повтор не начисляет награды снова.
- Проверка revision запрещает устаревшему экрану переписывать новое состояние;
  обычное save не может удалить/изменить уже принятые истории. Для явного импорта
  архива используется отдельная полная замена.
- storyStorageVersion1 и storyEvents находятся внутри JSON-агрегата, входят в
  существующий архив с контрольной суммой. Индексы receipts/events в Room
  восстанавливаются из того же агрегата. Старые принятые рассказы отмечаются
  LEGACY_EPISODE, а не превращаются в доказанные атомарные факты.
- storyFeedback: хранение/проверка оценок, причин, области и комментария;
  обычный UI-save не теряет эти поля. Интерфейс оценок и отправка предпочтений
  модели остаются этапами4–5; никаких запросов ИИ ради оценки сейчас нет.
- RestoreRecoveryJournal (AtomicFile+checksum) сохраняет прежние настройки и книгу
  до внешних записей. Commit-маркер сохраняется вместе с Room restore.
  При отсутствии маркера стартовое восстановление возвращает прежние внешние
  данные; при наличии сохраняет новые. Шанталь откатывается самой Room-транзакцией.
  Startup gate подключён к MainActivity, координатору тренировок и worker возврата.

После оптимизации неизменившегося UI-save — повторный итоговый прогон (см. ниже).

Новые тесты: v5→v6 с сохранением тренировочной таблицы и проверкой схемы Room;
rollback aggregate/event при конфликте receipt; однократный legacy import и

сбой SQLite после записи receipt; запрет устаревшего writer; архив с receipts,
событиями и feedback; симуляция двух точек прерывания restore (до/после commit).
Прежние проверки тренировок, backup, UI, генерации и карты входят в общий прогон.
Старые тесты, очищавшие только SharedPreferences, адаптированы к Room.
