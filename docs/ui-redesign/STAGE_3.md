# UI/UX v2 — этап 3: статистика и журнал

База: локальные этапы 1–2, HEAD bc045f0, ветка feat/velaris-ui-cleanup.
Новых APK, commit/push/merge нет. Версия/подпись не менялись.

## Реализовано

- Главная страница статистики: две метрики — currentStreakDays и
  totalHoldSecondsAllTime из прежнего WeeklyOverviewState. Форматирование
  секунд не меняет определение чистого удержания.
- Один месячный календарь: реальное completedCount каждого локального дня,
  нули/двузначные значения, текущий/выбранный день, заморозки. Поддерживаются
  предыдущие месяцы и високосный февраль; будущий переход ограничен доступными датами.
- Календарь использует полную ширину страницы, а метрики/переходы сохраняют поля.
  На обычных 360dp семь зон >=48dp помещаются; на очень узком экране сетка
  прокручивается горизонтально вместе с днями недели, с явной подсказкой.
- Отдельные страницы: день статистики, журнал, детали выбранного занятия,
  подробная аналитика. Сохраняются Back/выбранный месяц/дата/позиция списка.
  Предыдущие графики, жетоны, история/заморозки доступны в подробной аналитике,
  не дублируются на первичной странице.
- Журнал показывает реальные основные/свободные занятия и сохранённые
  незавершённые/остановленные попытки. Completion — единственный признак зачёта:
  один run.status=COMPLETED без receipt не считается выполненным занятием.
  Demo исключён явно из области «реальных занятий», как в прежней статистике.
- Детали сохраняют записанные локальные даты/часовой пояс, протокол, факт
  завершения, подтверждённую активность, нагрузку и причину прерывания.
  Legacy-записи без run/slot не пропадают; оценочная длительность помечается.
- Длинный журнал показывает по 50 строк с «Показать ещё»; остальные записи
  не удаляются. Есть loading/error/retry/честный empty state. Обновления отменяются
  при новом запросе; чтение журнала запускается при открытии журнала/деталей,
  а не при каждом открытии основной статистики.

## Данные

Новый WorkoutJournalRepository — только проекция существующих DAO-запросов
getRealWorkoutRuns/getRealWorkoutCompletions/getRealDailySlots в одной
согласованной транзакции чтения. Новых таблиц/миграций и сохранённого второго
счётчика нет. Канонические серии/удержание/энергия/free/plan/demo/заморозки
считаются прежним кодом. CalendarDaysByDate содержит старые даты с записями;
записи за пределами стандартного шестимесячного окна не отрезаются журналом.

Room schema/DAO/WorkoutPersistenceRepository, Preferences/ключи/Keystore,
награды/Шанталь, таймер/service/audio, backup/recovery, appId/версия/подпись
и браузерная часть не менялись. Числа из скриншотов не записываются в приложение.

## Проверки и результат

- Новый read-only тест устанавливает SQLite-триггеры, запрещающие INSERT/UPDATE/
  DELETE тренировок/завершений/слотов, и успешно читает журнал. До/после совпадают
  WeeklyOverviewState (включая серию/заморозки/время), энергия и реальные зачёты.
- Проекция проверяет demo, free/plan, legacy без метаданных, остановленные и
  неподтверждённые попытки, переход через полночь без переноса в новый часовой пояс.
- UI: 320dp/150%, високосный февраль, 12/0 сессий, заморозка, выбор даты,
  paging 51 записи, ошибка/повтор без ложного пустого журнала.
